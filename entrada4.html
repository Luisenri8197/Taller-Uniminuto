Seguridad en el Desarrollo de Software

Caso práctico de aplicación

Publicado para la actividad académica de Cifrado Asimétrico | UNIMINUTO

Con el fin de aterrizar los conceptos vistos en las entradas de este blog, se propone el siguiente caso de aplicación bajo el lenguaje Java.

Contexto de caso

Durante el desarrollo de modulos como microservicios, generalmente se ve la necesidad de transmitir tokens para autenticación o bloques de datos firmados para garantizar la integridad y autenticidad del emisor y el mensaje. Para este fin se hará uso de librerías dedicadas de Java como security y crypto, con el fin de demostrar como se pueden generar claves tipo RSA para el cifrado de un mensaje institucional por medio de la clave publica y descifrandolo por medio de clave la privada del receptor.

Estructura

Bajo una estructura Maven o Gradle se configura la clase principal AsymmetricEncryptionDemo.java la cual ejecuta las siguientes instrucciones.

Generación de Claves

Se realiza la inicialización de las claves con el algoritmo RSA y una longitud de 2048 bits.

Java

KeyPairGenerator keyGen = KeyPairGenerator.getInstance("RSA");
keyGen.initialize(2048);
KeyPair pair = keyGen.generateKeyPair();
PublicKey publicKey = pair.getPublic();
PrivateKey privateKey = pair.getPrivate();

Cifrado del mensaje

Se captura el mensaje a cifrar en texto claro y es procesado mediante una instancia de Cipher inicializada con la clave pública generada.

Java

Cipher cipher = Cipher.getInstance("RSA");
cipher.init(Cipher.ENCRYPT_MODE, publicKey);
byte[] encryptedMessage = cipher.doFinal("Datos confidenciales del sistema".getBytes(StandardCharsets.UTF_8));

Descifrado del mensaje

Por el lado del receptor, el array de bytes que fué cifrado se revierte haciendo uso exclusivamente de la llave privada que corresponde.

Java

cipher.init(Cipher.DECRYPT_MODE, privateKey);
byte[] decryptedMessage = cipher.doFinal(encryptedMessage);
String originalText = new String(decryptedMessage, StandardCharsets.UTF_8);

Al realizar el proceso de cifrado y descifrado con ésta metodlogía se puede evidenciar que el mensaje en texto claro fué entregado con éxito, solo mediante el uso de una llave pública y privada exclusiva del emisor y receptor.

Nota de Arquitectura / Desarrollo Seguro:

A modo ilustrativo, encriptar información por medio de una clave pública hace que solamente quien generó esa llave sea capaz de desencriptar el mensaje, nisiquiera el propio emisor podrá decodificar el criptograma, esto pone en perspectiva lo seguro que es este sistema.

  • Maillo, J. (2017). Sistemas seguros de acceso y transmisión de datos (pp. 76-102). RA-MA Editorial.
